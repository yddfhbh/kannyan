# TETR.IO 수동 계정 연동

`/리오로그인 유저:<Discord User> 닉네임:<TETR.IO 닉네임>`은 `interaction.user.id === '635107514471415808'`인 경우에만 실행된다. 다른 사용자는 API 조회 및 저장 전에 ephemeral 응답으로 거부된다. 허용된 사용자의 성공·오류 응답도 ephemeral이다.

TETR.IO 계정 존재 여부를 기존 조회 함수로 검증하고 API가 반환한 닉네임을 소문자로 저장한다. 없는 계정과 API 오류의 메시지를 구분한다. API 조회 또는 파일 저장이 실패하면 기존 매핑을 유지한다.

## 저장

- 파일: `<DATA_DIR>/tetrio-user-links.json`
- 디렉터리 선택: `TETRIO_LEAGUE_DATA_DIR` → `DATA_DIR` → 기존 기본값 `~/discord-bot-data`
- 형식: `{ "version": 1, "links": { "Discord User ID": "tetrio_username" } }`
- 최초 필요 시 파일을 읽으며, 조회와 등록이 같은 로딩 Promise를 공유한다. 손상된 파일은 오류로 처리하고 덮어쓰지 않는다.
- 하나의 봇 프로세스에서 등록을 큐로 직렬화한다. 기존 매핑을 복사하고 같은 디렉터리의 고유 임시 파일에 기록한 다음 rename한다. 디스크 저장 성공 후 메모리에 반영한다.
- 개인정보성 매핑과 임시 파일은 `.gitignore`로 제외한다. 운영 데이터 삭제·마이그레이션은 필요 없다.
- 같은 파일에 여러 봇 프로세스가 동시에 쓰는 구성은 지원하지 않는다. 기존 운영 방식처럼 단일 봇 프로세스로 실행한다.

## 조회 순서와 적용 범위

1. 명시한 닉네임 및 기존 다중 닉네임·숫자 스탯 등의 특수 입력 처리
2. 기존 공식 Discord 연동 조회 (기존 `842312482622144522` → `pyhok` 고정 매핑 유지)
3. 공식 API 검색 결과가 정상적인 빈 배열인 경우에만 수동 연동 조회
4. 양쪽 모두 없으면 기존 `assets/teto-babu.jpg` 첨부

공식 API의 타임아웃·서버 오류·잘못된 응답에는 수동 매핑으로 넘어가지 않는다. 기존 API 캐시 및 이미지 생성 경로를 재사용한다.

적용: `/테토`, `/스탯`, `/ts`, `/업적`, `/그래프`, `/스타일`, `/비교`, `/전적`, `/퀵플`, `/익스퀵플`, `/40라인`, `/블리츠`, `/퀵플기록`, `/익스퀵플기록`, `/40l기록`, `/블리츠기록` 및 기존 대응 `%` 명령어 (`%teto`, `%ts`, `%psq`, `%sq`, `%vs`, `%tetra`, 최근 리그 전적 목록 등). `%` 명령어의 멘션·답장 대상 판별은 유지하고, 판별한 Discord ID를 공통 조회에 전달한다.

`/분석` 및 대응 `%` 명령어의 계정 기반 최근 경기 조회도 동일한 공통 조회를 사용한다. 리플레이 파일 첨부 분석, 전체 리더보드, 랭크컷은 기존 처리 그대로다.

슬래시 명령어의 미연동 안내도 기존 이미지 첨부 생성기를 재사용한다. 명시한 닉네임이 존재하지 않는 오류는 기존 텍스트 안내를 유지한다.

## 검증 및 배포

`test/tetrio-account.test.js`는 임시 디렉터리와 mock API를 사용해 권한, 정상 등록, 없는 계정, API 장애, 재등록, 재시작, 동시 저장, 손상 데이터 보호, 공식/수동/명시 입력 우선순위, 고정 매핑, 명령어 옵션, 미연동 이미지 응답, 멘션·답장 대상 전달을 검증한다. 실제 운영 데이터 및 외부 계정을 수정하지 않는다.

로컬 구현 시 전체 `npm test` 314개 통과. 샌드박스 내 기존 챗봇 검증 테스트의 `spawnSync EPERM`은 권한 제한 밖에서 재실행해 통과했다. 변경한 JavaScript 파일의 `node --check` 통과.

배포 시 기존 영구 DATA_DIR 설정을 유지하고 봇을 재시작한다. 별도 승인 후 `npm run register`로 새 명령어를 등록해야 한다. 명령어의 `default_member_permissions`는 `0`이다. 지정 운영자가 서버 관리자가 아니라면 Discord 서버의 앱 명령어 권한 설정에서 해당 사용자에게 `/리오로그인` 사용을 허용해야 한다. Discord 관리자가 명령어를 볼 수 있더라도 실행 시 정확한 ID 검증으로 거부한다. 등록 API로 특정 사용자 허용 목록을 직접 설정하지 않는다.

이번 작업에서는 commit, push, production deploy, 실서버 명령어 등록을 수행하지 않는다. 실제 Discord에서의 실행 확인은 명령어 등록 후 별도로 필요하다.
