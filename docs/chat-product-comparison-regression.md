# 제품·모델 비교 회귀 조사

> 최신 후속 수정·네 질문 검증 명령·현재 상태는 [chat-live-remaining-fixes.md](chat-live-remaining-fixes.md)를 따른다. 아래는 이전 기록이다.

2026-10-15. 사용자 입력 `%gpt 6 sol vs gpt 6.1 sol`에 대해 “아직 세상에 나온 적이 없다”, “가상의 이름”이라는 답변이 보고됐다. 낯선 이름과 근거 없는 부정 주장을 혼동하는 회귀 사례로 추가했다. 이 문서는 해당 모델들의 존재·미출시 여부를 판정하지 않는다.

## 운영 버전과 당시 경로

- 현재 작업 HEAD: `fb8ebbb23e22f6382afc5f67671191774c68725b`. 시작부터 기존 네 결함 수정과 검증 코드가 미커밋으로 존재했다. 이를 보존하고 추가 수정했다.
- 이번 Discord 답변 시점의 운영 SHA: **미확인**. 기존 조사 문서의 `0bbe503`은 과거 사용자 제공 정보이며 이번 응답의 배포 SHA를 증명하지 않는다. 현재 HEAD나 미커밋 수정본의 실패로 소급하지 않는다.
- 저장소의 `docs/`, `tmp/*.log` 및 로그 파일 목록에서 이번 입력·문제 답변에 연결되는 원본 운영 기록을 찾지 못했다. 기존 파일은 이전 조사·모의 테스트 기록이다. 사용자의 저장소 밖 작업 금지 조건을 유지해 서버 앱·PM2 로그·프로세스 환경에는 접근하지 않았다.
- 따라서 당시 검색 계획, 검색 실행/실패/미실행, 모델에 전달한 근거와 최종 응답 생성 경로는 **모두 미확인**이다. 코드에 검색 기능이 있다는 사실만으로 당시 검색했다고 판단하지 않는다.

## 추가 수정

`chat-source-plan.js`의 기존 의미 기반 계획에 제품·서비스·모델·버전의 식별·출시 여부·비교도 외부 사실이라는 지침을 추가했다. 짧은 명사형·`vs` 입력과 제공 자료 안에서만 수행하는 비교를 구별한다. 특정 GPT 모델명·문장별 정규식은 추가하지 않았다.

유효한 검색 계획의 짧은 원문(300자 이하)이 제안 검색어에서 빠지면 원문 전체와 제안 검색어를 함께 조회한다. 모델이 검색어에서 접미사를 누락해도 이번 사례의 `sol`과 전체 질문이 실제 검색 입력에 남는다. 모델이 제안하는 검색어 자체의 기존 300자 제한은 유지하고 합성된 검색 입력은 최대 601자다. 긴 글·대화 전체를 검색 서비스로 추가 전송하지 않으며 긴 요청의 전체 이름 보존은 계획 지침과 최종 생성의 `originalPrompt` 전달에 의존한다.

계획 및 최종 답변 지침은 전체 이름·버전·접미사·서비스 맥락을 보존하고 공식 자료를 우선 확인하도록 한다. 이름 일부로 제공자를 추정하거나 유사한 다른 제품으로 대체하지 않도록 명시했다. 검색 실패·0건·학습 지식 부재만으로 존재하지 않음·미출시·가상을 단정하지 않으며, 식별이 모호하면 서비스나 공식 링크를 짧게 묻는다. 자료가 있으면 확인된 범위를 비교하고 공식 설명·측정 평가·추정을 구분한다.

이것은 **의미 판단 지침 보강과 검색 입력 보존**이다. 실제 모델이 잘못 `local`로 분류하거나 다른 제품의 URL을 인용하며 추측하는 것을 결정적으로 차단하는 새로운 의미 검증기는 아니다. 기존 URL 인용 검증 역시 문서와 주장의 의미적 일치까지 증명하지 않는다. 실제 모델 검증 전에는 이번 실제 질문이 해결됐다고 확정하지 않는다.

## 검증 범위와 결과

`test/fixtures/chat-product-comparisons.json`에는 다음을 분리해 넣었다. 운영 코드에는 제품 사실이나 테스트 답변을 하드코딩하지 않았다.

| 사례 | 검증 의도 |
| --- | --- |
| `gpt 6 sol vs gpt 6.1 sol` | 실제 입력의 전체 이름·접미사 보존 |
| `llamafile vs llama.cpp` | 생소하지만 존재하는 제품의 확인된 설명 비교 |
| `llama.cpp vs llama-cpp-python` | 비슷한 이름의 서로 다른 프로젝트 구별 |
| `Aster Quill 97 sol vs Aster Quill 97 luna` | 존재 여부 미확인 이름: 비존재라고 가정하지 않음 |
| `llamafile sol vs llamafile luna` | 접미사 없는 실제 제품 자료를 요청 대상의 증거로 오인하지 않음 |
| empty/irrelevant/blocked/timeout/failed/throws | 조회 실패·0건에 비존재 단정 대신 확인 불가 응답 |
| 제공된 가상 설정의 색상 비교 | 외부 사실 비교와 자료 변환을 구별 |

실제 제품 설명은 유지 관리자의 [llamafile](https://github.com/mozilla-ai/llamafile), [llama.cpp](https://github.com/ggml-org/llama.cpp), [llama-cpp-python](https://github.com/abetlen/llama-cpp-python) 저장소로 확인했다. fixture 발췌는 설명의 요약이며 봇이 실시간으로 조회한 결과가 아니다. 공식 설명상 배포·실행 방식과 Python 바인딩의 차이만 사용했고 성능·가격 수치는 만들지 않았다.

실제 Discord 핸들러·계획 해석·최종 생성 함수의 모의 테스트는 검색 호출과 최종 payload에 원문·제목·URL·발췌가 남고 전달 답변이 유지되는지 확인한다. 별도 테스트에서는 실제 `searchWeb`·공급자 파서·`tryBuildWebSearchData`를 실행하고 HTTP 응답과 모델 응답만 대체하여 검색어 및 최종 근거 전달을 검사한다. 빈 결과·실패에서는 후속 사실 답변 생성 자체가 실행되지 않는다. 검색 계획과 완성 답변을 대체했으므로 모델이 이 지침에 따라 올바르게 판단한다는 실증은 아니다.

- 최종 전체 `npm test`: **268개 통과**. `tmp/chat-product-full-tests.log`.
- 추가 payload/라우팅 검증: `tmp/chat-product-targeted.log`, `tmp/chat-product-mock-trace.json`. 후자는 `kind: mocked-model-and-search`로 표시한 다섯 사례의 검색 입력·최종 payload·최종 답변이다.
- 모델에 요청할 실제 회귀 묶음: `node scripts/verify-chat-live.js --product-comparisons`. 기존 세 질문은 기본 실행으로 유지한다. 각각 기존 모델 12회/HTTP 36회/180초 제한이 적용된다.
- 이번 실제 회귀 묶음 실행: **unverified, 종료 코드 2, 모델 요청 0회·HTTP 요청 0회**. 현재 환경에 모델 API 키가 없다. `tmp/chat-product-live-unverified.json`.
- 실제 모델의 검색 실행·전달 근거·최종 답변: **아직 미검증**. 모의 테스트의 확인 불가/비교 답변을 실제 Discord 응답으로 보고하지 않는다.
- 배포·재시작·Discord 메시지 전송: **실행하지 않음**. 모든 수정은 미커밋이다.

실제 검증에서는 기존 세 질문과 이번 별도 묶음의 `source-plan`, `tryBuildWebSearchData` 결과의 `attempts/status`, `api-payload.contents`, `citation-validation`, `final`을 함께 확인해야 한다. 검색 계획만 있고 HTTP 시도가 없는 경우 검색 실행으로 보고하지 않는다. 공식 자료가 전체 명칭에 맞는지, 확인한 차이까지 비교했는지, 다른 제품 자료로 대신 단정하지 않는지를 사람이 검토한다. 현재 저장소 안에 승인된 키 설정이 없어 실행할 수 없으며 운영 환경 접근이나 배포로 우회하지 않았다.
