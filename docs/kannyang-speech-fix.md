# 냥체 생성 지침 및 후처리 보호 범위 수정

2026-10-16. 시작 HEAD `0aba7dbbe30ec7975e2d45df3d76acaf9922c7ab`. 시작 시 미커밋 변경은 없었고 관리 브랜치를 유지했다.

## 원인과 처리 경로

1. `src/index.js`의 `geminiSystemInstruction`에 `geminiStyleRequestHandlingSystemInstructionLines`가 포함된다. 기존 지침은 냥체·존댓말 뒤 기계적 접미 금지·일부 관찰형 예시를 제공했지만, 현대 한국어를 바탕으로 하오체·명령조를 피하라는 일반 지침이 없었다.
2. `generateGeminiAnswer`는 모델 JSON의 `answer`를 읽는다. 제보 문장을 고정 모델 응답으로 주입하면 후처리 전부터 `물어봐 다오냥`이 존재한다. 당시 운영 모델 원본 로그는 제공되지 않았으므로, 과거 원본을 직접 관측했다고 주장하지 않는다.
3. 응답 검사·기억 출처 추출 후 `sanitizeGeminiAnswer` → `normalizeKannyangSpeech` → `normalizeDiscordMarkdown` → `applyCustomEmojiAliases` → 인용 검증 순서로 처리한다. 기존 말투 치환에는 `다오`·`하오`를 생성하는 규칙이 없다. 제보 문장은 기존 후처리를 그대로 통과한다. 별도로 기존 전역 말투 치환은 코드·URL·출처·인용 원문까지 바꿀 수 있었다.
4. `handleGeminiFallbackMessage`가 답변과 기억 출처를 조합하고 메시지를 나눠 Discord 전송 함수에 넘긴다. 여기서 새 어미를 만들지 않는다.

## 수정 범위

- 생성 지침에 친근한 현대 한국어, 문맥에 맞는 안내·허용·제안, 하오체·불필요한 명령조 회피를 추가했다. 모든 문장에 냥을 붙이지 않으며 정상적인 `이다냥·있다냥·알려줄게냥`을 유지한다.
- 후처리는 기존 제한된 교정을 유지하고, 종결의 연속된 냥만 정리한다. `다오냥 → 특정 표현` 치환표나 어미별 새 예외를 추가하지 않는다. 하오체 문장 전체의 자연스러움은 생성 단계에서 해결하며, 모델이 여전히 하오체를 내면 결정적 후처리로 교정된다고 보장하지 않는다.
- 코드 펜스(미완성 포함)·인라인 코드·URL·링크·출처 표기·인용 원문을 보호한 뒤 스타일 후처리를 적용한다. 이후 마크다운·이모지 처리에서 코드 들여쓰기나 출처가 바뀌지 않도록 공통 생성 경로도 같은 보호 함수를 사용한다.
- 검색·위키·기억·날짜·모델 선택·fallback 로직은 변경하지 않았다. 말투 교정용 모델 요청을 추가하지 않았다.
