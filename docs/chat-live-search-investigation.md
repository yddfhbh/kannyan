# 검색 경로 조사 및 그림 생성 제거 — 실계정 검증 미완료

기준: `0bbe503`. 시작 작업 트리는 깨끗했으며 기존 변경·운영 데이터·운영 `.env`를 수정하지 않았다.

## 실제 조회에서 확인한 사실

2026-10-15 작업 환경에서 샌드박스 기본 네트워크는 연결 실패했다. 승인된 외부 조회에서는 다음을 관측했다. 운영 프로세스에서 얻은 결과가 아니다.

- `부산 오늘 날씨`: DuckDuckGo HTTP 200, 파싱 10건. 예: https://ko.meteocast.net/today-forecast/kr/pusan_2/ , https://www.korea247.kr/south-korea/busan/weather-busan/ . 스니펫의 온도만으로 실행일의 실제 날씨를 확정하지 않았다.
- `최신 AI 뉴스`: 첫 조회는 DuckDuckGo HTTP 202 챌린지와 Naver HTTP 200을 기존 차단 조건으로 분류했다. Naver 본문을 추가 조사하니 제목은 `최신 AI 뉴스 : 네이버 검색`이고 `captchaApi`는 JavaScript API 설정이었다. 정상 검색 페이지를 차단으로 오인하는 조건을 실제 HTML에서 확인했다. DuckDuckGo 재조회는 HTTP 200, 10건이었고 상위에는 AIWire·Ai픽 등 포털이 있었다. 기사 본문·발행일은 아직 검증하지 않았다. 제공자가 매번 차단된다는 결론은 내릴 수 없다.
- Naver 차단 판정을 단순 `captcha` 문자열 검색에서 실제 챌린지 요소·페이지 제목 검사로 바꾸었다. 정상 페이지에 captcha API 설정이 있는 경우의 회귀 테스트를 추가했다.

이 원인 하나가 사용자에게 보고된 세 운영 응답 전부를 설명한다고 단정하지 않는다. 실제 모델의 원본 응답·운영 Meilisearch·후속 모델 응답을 아직 얻지 못했다.

## 코드에서 확인·수정한 경로

- 검색 계획이 없거나 잘못된 첫 응답은 복구 요청 없이 끝날 수 있었다. 답변과 `sourcePlan`의 `responseSchema`를 지정하고, 계획 검증 실패 시 동일 문맥으로 최대 1회만 복구한다. 실패를 검색 불필요나 정상 0건으로 표시하지 않는다. 명시적 검색은 기존의 제한된 원문 조회를 유지한다. 구조화 출력은 [Google 공식 문서](https://ai.google.dev/gemini-api/docs/structured-output)를 참고했다. 운영 주 모델·fallback의 실제 지원 여부는 미검증이다.
- 정상 HTTP 응답에서 파서가 아무 결과도 찾지 못하면 정상 0건이 될 수 있었다. 제공자의 명시적 빈 결과 표식이 없으면 `parse-error`로 구분한다. 공급자별 query·HTTP 상태·결과 수·상태를 반환하며 평소 로그에 질문 원문을 새로 기록하지 않는다.
- 문맥 예산 적용 시 일반 문자열 창으로 근거를 잘라 URL이나 출처와 본문 관계가 유실될 수 있었다. 근거는 문서 단위로 배분하고 완전한 URL과 발췌를 함께 보존한다.
- 기존 URL 검사는 괄호가 있는 위키 URL을 잘랐으며 인코딩 표현 차이를 그대로 비교했다. URL 정규화와 괄호 처리를 수정했다. 현재 전달 문맥의 명확한 출처 ID만 URL로 해석하며, 없는 ID·충돌하는 ID·다른 요청의 ID·허위 URL은 거부한다. 인용 검증을 끄지 않았다.
- 자기소개·기억·제공 자료 기반 답변과 외부 답변을 나누는 기존 경로 및 위키 나이의 정확한 문서/생년월일 검증을 유지했다. 조회 예정 문구나 기다려 달라는 약속을 계획의 자체 답변으로 쓰지 않도록 지시했다. 실제 모델의 준수 여부는 미검증이다.

## 그림 생성 제거 범위

`src/cloudflare-image.js`, `src/image-generation-request.js`, 전용 테스트, 자동 생성 의도 감지, 사용자별 생성 쿨다운, Gemini 프롬프트 재작성, Cloudflare 호출, 생성 완료 기억 기록을 제거했다. 시스템 기능 안내·README·`.env.example`의 전용 Cloudflare 키 예시를 정리했다. 운영 `.env`의 키는 읽거나 출력·삭제하지 않았다. 생성 전용 외부 패키지는 없어서 package 의존성 변경은 없다.

`gemini-image.js`, `gemini-image-routing.js`, `GEMINI_IMAGE_MAX_BYTES`는 첨부/답장 이미지 이해와 공유하므로 유지했다. 체스 이미지→FEN, 카드 렌더링, 감정 이미지 및 관련 의존성도 유지했다. 슬래시 명령에는 별도의 그림 생성 명령이 없었다.

## 내부 검증 진입점

`node scripts/verify-chat-live.js`

현재 런타임의 환경 설정을 로드하고 실제 `handleGeminiFallbackMessage`, 답변 생성, 모델/키 fallback, 웹 검색, 위키 조회, 문맥 배분, 인용 검증 함수를 실행한다. Discord 로그인·전송, 운영 기억 파일 읽기/쓰기를 하지 않는다. 세 고정 공개 질문은 하나의 격리된 메모리 세션에서 순서대로 실행해 이전 질문의 문맥이 있을 때도 비교할 수 있다. 모델 원문은 이 명시적 진단 실행의 고정 질문에 대해서만 출력한다. 운영 일반 대화의 원문을 수집하는 로깅 기능은 추가하지 않았다.

출력에는 질문별 검색 계획 파싱, 원본 모델 JSON과 실제 모델명, 공급자별 HTTP 상태·query·결과 수, 조회 근거와 최종 모델에 실제 전달한 근거, 인용 검증 전후 답변, 최종 전송 텍스트가 포함된다. 결정적 위키 나이 경로에서는 후속 모델 호출이 없는 것이 정상이며 생년월일/기준일로 계산한 최종 답변을 출력한다.

실행 결과: API 키가 없는 것을 확인해 `status=unverified`, 종료 코드 2를 반환했다. 실제 모델 응답을 모의 응답으로 대체해 성공으로 보고하지 않았다. 별도로 모의 fetch를 주입해 스크립트 자체의 세 경로가 실행되는 것은 확인했다. 이 확인은 실계정 검증 결과가 아니다.

## 검증 상태와 남은 작업

`npm test`: 38개 테스트 파일 통과. 생성 전용 테스트 파일 1개 제거로 기존 39개에서 줄었다. 구문 검사와 `git diff --check` 통과. 회귀 항목에는 검색 차단 오탐, 파싱 실패/정상 0건, 구조화 계획/1회 복구, 혼합 답변 보존, 출처 인코딩/괄호/ID, 근거 예산 보존 및 기존 위키 나이/이미지 경로가 포함된다.

현재 작업 런타임에는 `.env`와 모델/Meilisearch 키가 없다. 서버 콘솔의 `/home/ubuntu/discord-bot-new` 접근은 `Permission denied`였다. 승인된 운영 설정 실행 진입점이 필요하며 비밀값을 대화에 보내도록 요구하지 않았다. 생일 `2007-09-14`를 실제 문서의 값으로 확인한 것처럼 보고하거나 기대 나이를 최종 답변에 하드코딩하지 않았다.

운영 상태 읽기: PM2 `discord-bot` (id 5) `online`, health `{"ok":true,"discordReady":true}`. 운영 SHA 재조회는 앱 접근 권한 때문에 미검증이다. 새 변경은 실계정 검증이 끝나지 않아 배포하지 않았다. 사용자가 제시한 기존 운영 SHA는 `0bbe503`이며 재검증된 배포 SHA로 보고하지 않는다.
