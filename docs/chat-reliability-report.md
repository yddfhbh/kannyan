운영 접근으로 PM2의 `discord-bot`이 online인 것은 확인했다. 그러나 프로세스의 `/proc/.../cwd`·환경과 운영 홈 디렉터리 접근이 권한으로 차단되어 **운영 배포 SHA, 적용 모델 설정, 최근 성공 모델, 오류 이력, 전환 빈도는 확인하지 못했다**. 재시작 횟수를 모델 전환 횟수로 해석하지 않았다. 현재 작업 환경에는 `.env`와 API 키가 없다. 공개 `https://pyhok.com/w/파이호크` 원문도 조회할 수 없어, 문제 답변의 생년월일이 실제 문서에 존재하는지는 **미확인**이다. 실제 Meilisearch 주소·인덱스·인증·공개 필터의 운영 응답도 확인하지 못했다.

코드 기본 텍스트 모델 순서는 기존 그대로 `gemini-3.6-flash` → `gemini-3.5-flash` → `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` → `gemini-2.5-flash` → `gemma-4-26b-a4b-it` → `gemma-4-31b-it`이다. 기본 vision은 `gemini-flash-latest`이고 기존 vision fallback을 보존했다. `.env.example`의 기본 텍스트 값은 별도로 `gemini-3.5-flash-lite`다. 실제 운영 값과 혼동하면 안 된다. 모델 ID를 새로 추가하거나 과금 설정을 바꾸지 않았다. API 모델 목록·각 모델의 JSON/system instruction 지원은 실계정에서 확인하지 못했다. 명시적인 옵션 미지원 400은 다른 모델로 넘기고, 일반 400은 같은 요청을 다른 키로 반복하지 않는다. JSON 요구와 보안 지침을 제거하는 자동 호환 변환은 하지 않는다. 공유 호출자의 기존 모델/이미지/체스 payload를 바꾸지 않고 일반 챗봇만 새 fallback 정책을 사용한다.

운영에서 확인할 사항은 `PYHOK_WIKI_SEARCH_ENABLED`(코드 기본 false), `PYHOK_MEILI_URL`(기본 `http://127.0.0.1:7700`), `PYHOK_MEILI_INDEX`(기본 `TheTreeDocuments`), `PYHOK_MEILI_KEY`의 존재 여부와 공개 문서 필터 지원이다. 실제 설정값은 이번에 변경하지 않았다. 기존 환경에 `GEMINI_MEMORY_MAX_ENTRY_LENGTH=4000`이 명시돼 있으면 그 값은 계속 적용된다. 필요할 때 운영자가 새 기본값과 비교해 조정할 수 있다. 배포 시에는 먼저 실제 계정의 모델 목록과 기존 요청 옵션을 확인하고 제한된 실서비스 질문으로 평가해야 한다.

조회량은 사실 질문과 이미지+사실 질문에서 늘 수 있다. 일반 웹 조회는 총 8초 제한 안에서 DuckDuckGo와 필요 시 Naver를 사용하고, 관련 상위 결과 본문은 기존 SSRF 방어를 거쳐 **1개, 전체 3초**만 추가 조회한다. 위키 기본 제한은 기존 5초이며 웹과 병렬이다. 사용자가 직접 준 URL의 기존 별도 조회 경로는 유지했다. 무제한 재검색이나 불확실한 답변 뒤 추가 모델 재생성은 하지 않는다. 날짜 질문은 검색·모델 호출을 없앴다. 모델 입력 문맥은 여전히 기본 32,000자 이내이나 과거보다 더 많은 대화 문자를 사용할 수 있다. entry 기본 상한 증가로 기억 파일의 잠재 크기는 늘어난다. 실제 지연·토큰·요청량의 변화는 운영 측정을 하지 않아 수치로 단정하지 않는다.

남은 한계는 검색 관련성의 언어 기반 선별, 모델이 출처의 내용을 정확히 해석하는 정도, 위키 자체의 오래되거나 잘못된 서술이다. URL 검증은 사실의 진실성을 보장하지 않는다. 생년월일 추출은 오귀속을 피하기 위해 보수적으로 제한했으므로 비정형 문장·별칭·리다이렉트·모호한 생일은 확인 불가로 처리할 수 있다. 일반 검색의 snippet만으로 생년월일을 확정하지 않는다. 지원 지역명 또는 IANA 시간대를 사용하며 모호한 지역은 추가 정보가 필요할 수 있다. 유실된 과거 160자 문맥이나 이미 저장 전에 잘린 원문을 복원하는 작업은 하지 않았다.

## 2026-10-15 후속 최종 검토

위 내용은 최초 구현 검증 시점의 기록이다. 후속 검토에서 저장소의 `AGENTS.md` 부재와 기존 변경을 다시 확인했다. 챗봇 관련 파일만 커밋 대상으로 선정했으며 체스·TETR.IO·V-ARCHIVE 구현은 변경하지 않았다. 공유 API 호출자의 기존 400 키 전환 정책은 보존하고 새 오류 분류는 챗봇 전용 경로에만 적용했다.

추가로 최종 근거 문맥에 URL이 하나도 남지 않을 때 인용 검사가 그대로 통과하던 빈틈을 수정했다. URL 없는 단정과 허위 인용은 거절하고 확인 불가 응답은 허용하는 회귀 검증을 추가했다. 성공 로그에는 요청한 `model`과 API의 `modelVersion`에서 얻은 `responseModel`을 분리했다. API가 버전을 보고하지 않으면 `unreported`로 남기며 요청 모델로 대체하지 않는다. 실제 `%푝무위키 … 나이` 핸들러가 대상 문서의 검증용 생일로 계산하고 기억을 저장하며 웹/모델을 호출하지 않는 회귀 검증도 추가했다. 테스트 자료의 2000-10-15는 가상 자료다.

운영에서 전용 PM2 조회는 `discord-bot` online(PID 2285948, 재시작 15회)을 반환했고, 서버 내부 `http://127.0.0.1:8080/health`는 `{"ok":true,"discordReady":true}`를 반환했다. 이는 배포 전 상태이며 새 코드가 적용되었다는 뜻이 아니다. 운영 앱 경로 `/home/ubuntu/discord-bot-new`는 콘솔에서 `Permission denied`다. `/proc/2285948/cwd`, 프로세스 환경, PM2 오류 로그도 읽을 수 없었다. 따라서 운영 SHA·tracked/untracked 상태·실제 기본 모델/fallback·최근 실제 성공 응답 모델·오류 이력은 미확인이다. 비밀값은 출력하지 않았다.

서버에 설치된 전용 `discord_bot_deploy` 절차의 읽기 검토 결과 고정 `origin/main`을 fetch하고 tracked 변경이 있으면 중단하며, 후보 테스트 후 fast-forward와 PM2 재시작을 수행한다. `.env`, untracked 파일, 영구 데이터는 보존하도록 되어 있다. 그러나 이 도구에는 읽기 전용 상태 조회, 코드/설정 복구 지점 확보, health 실패 후 완전한 복구 기능이 없다. 저장소 `VM_DEPLOY.md`의 전체 tarball 재배포도 운영 변경을 확인·백업할 권한 없이 실행하면 안 된다. 현재는 요청된 사전 복구 지점과 운영 변경 보존을 검증할 수 없어 **배포·재시작을 실행하지 않았다**. 코드·설정·기억·데이터를 운영에서 수정하거나 복원하지 않았다. 재개에는 운영 앱의 SHA/status와 모델 설정·성공 모델·오류 로그를 비밀값 없이 조회하고, 코드/설정만 백업·복구할 수 있는 제한된 운영 기능이 필요하다. 새 기억/데이터는 복구 대상에서 제외해야 한다.

위키는 후속 검토에서 추가 확인되었다. **운영 서버에서** 공개 [파이호크 문서](https://pyhok.com/w/파이호크)를 GET하여 HTTP 200과 제목 `파이호크 - 푝무위키`를 확인했다. script/style을 제외한 HTML 프로필 표의 해당 행 원문은 `생일 2007년 9월 14일`이다. 따라서 문제 답변의 `2007-09-14`는 현재 위키 원문에 근거가 있다. 이는 위키 서술 확인이며 인물 정보 자체의 독립적 검증이나 문제 응답 당시 실제로 검색했다는 증명은 아니다. 2026-10-15 기준 해당 생일로 계산하면 만 19세다.

운영 서버 기본 Meilisearch 주소 `http://127.0.0.1:7700/health`는 HTTP 200, `{"status":"available"}`였다. 기본 인덱스 `TheTreeDocuments`에 `q=파이호크`, `anyoneReadable = true`로 인증 없는 읽기 전용 검색을 요청하자 HTTP 401 `missing_authorization_header`였다. 실제 봇의 인증키나 설정은 읽지 못했으므로 **봇의 인증 실패로 해석하면 안 된다**. 운영 봇의 활성화 여부·주소·인덱스·인증·공개 필터를 적용한 실제 검색 hit와 원문은 여전히 미확인이다.

Discord에는 테스트 메시지를 보내지 않았다. 운영 접근이 복구되어 배포가 끝난 뒤 사용자가 직접 같은 채널에서 확인할 입력은 `%오늘날짜`, `%오늘 날짜 검색해서 알아와`, `%푝무위키 파이호크 나이`다. 날짜 둘은 Asia/Seoul 서버 시계 기준 같은 날짜여야 한다. 위키 질의는 대상 문서와 생일 근거로 계산하거나 연결 상태에 맞춰 확인 불가를 안내해야 한다. 긴 조건 검증은 긴 메시지 중간에 `예산 15만원 이하, 빨간색 제외`를 넣어 보낸 뒤 `%내가 준 예산과 제외 조건을 다시 말해줘`로 이어 확인한다. 테스트 통과만으로 실제 모델의 이 조건 준수를 보장하지 않는다.
